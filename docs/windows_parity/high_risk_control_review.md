## Control boundary selected for implementation

1. A signed Windows host owns WebView2 navigation, browser profile, and the operator's privileged gesture. The existing Python/pywebview window is **not** that host: its page bridge and same-origin HTTP requests are not a trusted approval boundary.
2. The host and daemon communicate over a per-launch authenticated control channel. A random capability must be transferred through an inherited handle or equivalently protected channel, never in web content, a URL, a log, a persisted cookie, or an ordinary API body. A Windows named-pipe ACL alone is insufficient: another same-user process can meet that ACL. Ordinary loopback HTTP must not mint owner-local authority.
3. WebView2 page messages are untrusted requests, not approvals. The host verifies the top-level origin and renders a native modal containing the exact typed action, target and digest. Only a user gesture in that modal can produce an expiring, single-use grant. The daemon rechecks the action digest, scope and policy at consumption. Deny, timeout, navigation change and host crash all fail closed.
4. The signed broker runs protected executable effects inside an OS-enforced restricted/AppContainer process with a Job Object, scoped filesystem ACLs, inherited-handle allowlist, resource ceilings and no network capability unless the exact action explicitly permits it. A restricted token or Job Object alone is not filesystem/network isolation. `JobRunner` and plugin/MCP paths must converge on this backend; no bare-argv fallback.
5. Source tests must prove unrelated local requests, forged Origin/Host/body, replay, changed action, and missing host/broker are denied. Real Windows 10/11 installed-artifact tests must inspect token/capabilities and attempt file, process, descendant and socket escapes. Signature and same-artifact hash evidence remain release gates. Same-user malware with the ability to inject into or read the trusted host is outside a token-only proof and needs explicit OS-hardening/threat-model evidence.

Current state: the plugin/MCP raw fallback remains closed. The Inno script now selects the native WebView2 host, which implements a per-launch proof channel and native approval dialog for `/api/mode` and `/api/commands/dispatch` (`installer/windows_host/`, `core/native_control.py`). The packaged native broker passes its 16-test development-host isolation gauntlet, including the executable replacement race. It is not yet the backend for all protected effects, and the unsigned internal installer has not completed a clean-VM install. Remaining typed approvals, release signatures and installed-artifact attack tests are open. `JobRunner` refusal still does not cover in-process workspace writers, HTTP senders, browser actions, or wallet doors; those require their own trace and adapter gates. Do not claim equivalent utility/security or public readiness.
